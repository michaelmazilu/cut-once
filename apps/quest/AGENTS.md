# Rules for code in apps/quest (people and AI agents)

The app runs on a **Meta Quest 3**. Most of the work happens on laptops: Michael's Mac and the team's Windows
machines, in Unity with **Meta XR Simulator**. These rules make sure that what works on a laptop also works on
the headset. [README.md](README.md) explains how to set up and run it.

## The project

- **Unity 6000.6.2f1, exactly** (the version in `ProjectSettings/ProjectVersion.txt`), on macOS and Windows. Don't
  upgrade Unity or any package in `Packages/manifest.json` without asking the team. An upgrade rewrites files that
  everyone else then has to pull.
- **Always commit `.meta` files with their asset.** Never delete or regenerate them: the GUID inside is how scenes
  and prefabs find the asset.
- **The settings are code.** They live in `Assets/CutOnce/Editor/QuestSetup.cs`, and **Cut Once > Apply Quest 3
  settings** puts them back. To change a setting, change that file and the matching check in `QuestChecks.cs`,
  not just the Inspector.
- **Who owns what:** only A1 edits `Main.unity`, and each prefab has one owner. Rhythm owns `Assets/CutOnce/Copilot/`.
  `Assets/CutOnce/Scenes/QuestBaseline.unity` is generated by code, so don't edit it by hand.

## What works on the laptop but breaks on the Quest

These all behave correctly in the Editor and fail only on the headset, which is why they are rules.

1. **Anything that differs between the headset and the laptop goes behind an interface with two implementations.**
   The rest of the code must run identically in both. `#if UNITY_ANDROID && !UNITY_EDITOR` is allowed only inside
   the headset-side implementation.
   - **Camera photo:** `ICameraFrameSource`. On the headset, `Device/PcaFrameSource` uses MRUK's
     `PassthroughCameraAccess` (`Meta.XR`), never `WebCamTexture`, which in the Editor is the laptop's webcam, the
     wrong camera in the wrong place. In Meta XR Simulator on a Mac, `PassthroughCameraAccess` starts and gives the
     Quest 3 lens's pose and focal length (what `PartProjector` needs) but no pixels, so the Editor uses
     `FixtureFrameSource`, a stored photo. Never assume a live camera frame in the Editor.
   - **Server address:** read it from one config (`localhost` in the Editor; the laptop's Wi-Fi IP or the tunnel on
     the headset). Never hard-code `localhost` or `127.0.0.1`.
2. **StreamingAssets is not a folder on Android.** `File.ReadAllText(Application.streamingAssetsPath + ...)` works
   in the Editor and throws on the Quest. Load it with `UnityWebRequest`. Use `Application.persistentDataPath` for
   files you write.
3. **Permissions are asked for at runtime on the headset.** Ask for the microphone (`RECORD_AUDIO`) and the camera
   (`horizonos.permission.HEADSET_CAMERA`) before first use, and handle "denied". The Editor never asks.
4. **Custom shaders must support single-pass instanced stereo.** Use `UNITY_VERTEX_INPUT_INSTANCE_ID`,
   `UNITY_VERTEX_OUTPUT_STEREO`, `UNITY_SETUP_INSTANCE_ID` and `UNITY_INITIALIZE_VERTEX_OUTPUT_STEREO`, or the
   object is drawn in one eye only. Use URP shaders only: built-in lit shaders (Standard, Legacy) draw pink.
5. **See-through materials:** blend the alpha channel with One / OneMinusSrcAlpha, as URP does by default. With
   SrcAlpha, a 0.18 fill turns into 0.03, which is almost invisible over passthrough but looks fine in the Game view.
6. **Keep the camera's background transparent** (solid colour, alpha 0), and keep HDR and post-processing off.
   Passthrough shows through wherever the eye buffer's alpha is 0.
7. **Sizes are in metres, and line widths too.** The palette gives edge widths in pixels. On a Quest 3, one pixel is
   about 0.66 mm at 80 cm, so multiply by that. Screen-pixel lines have no fixed size in VR.
8. **IL2CPP strips code it thinks is unused.** Types that are only created by reflection (Newtonsoft JSON DTOs,
   anything found by name) need `[Preserve]` or an entry in `link.xml`. `JsonUtility` with `[Serializable]` is safe.
9. **Use UnityWebRequest for HTTP, and never block the main thread.** A blocked frame on the headset is a visible
   judder, not a pause.
10. **Don't allocate every frame.** Avoid LINQ, `string` building, `new` lists, and `Find*` or `GetComponent` in
    `Update`. The garbage collector's pauses show up as dropped frames on the Quest long before a laptop notices.

## Budgets

These come from Meta's Quest 3 guidance. The numbers live in `Assets/CutOnce/Diagnostics/QuestBudgets.cs`.

| | Budget | Measured where |
|---|---|---|
| Frame rate | 72 fps (13.9 ms per frame), no dropped frames | **Headset only** (`BudgetProbe` logs it). A laptop is several times faster |
| Draw calls | ≤ 300 | Same in the simulator as on the headset: `BudgetProbe` |
| Triangles | ≤ 1,000,000 | Same in the simulator as on the headset: `BudgetProbe` |
| See-through surfaces | ≤ 150 in view | Scene check |
| Textures | ≤ 2048 px | Scene check |

Every scene has a `BudgetProbe`. It warns in the Console when the plan loaded at runtime goes over budget.
Dynamic resolution stays off: the simulator cannot show it, and it softens the thin edge lines. Change that only
if the headset misses 72 fps.

## Before you push: the verification ladder

Say which step you reached. "Compiles in the Editor" is not "works on the Quest".

0. **Three-pillar contract.** Run `pnpm quest:pillars` and read
   [`docs/quest-three-pillars.md`](../../docs/quest-three-pillars.md) before changing vision, Copilot/provider,
   networking, build generation, schemas, analytics or data pipelines. A refactor must update its behavioural test and
   the contract gate in the same change; do not remove a fallback merely because a new primary path should work.
1. **Compiles.** No errors in the Console.
2. **Tests pass.** Run the EditMode tests in the Test Runner, or `pnpm quest:check` with the Editor closed. That
   also compiles the code as the Android build does, runs Meta's Project Setup Tool checks, and checks every build
   scene against the budget.
3. **Ready for the Quest.** **Cut Once > Check Quest readiness** reports 0 errors.
4. **Seen in the simulator.** Press Play with Meta XR Simulator active (Quest 3 profile, a synthetic room). Look at
   the change. `BudgetProbe` shows no warning. `pnpm quest:sim` (Editor closed) checks the simulator itself still
   stands in for the Quest 3: profile, eye buffer, passthrough, camera lens, budget.
5. **Seen on the headset.** Needed if the change touches anything in README's "only on the headset" list:
   permissions, network, frame time, or how it looks over real passthrough. On Windows, use Quest Link.

## For AI agents

- With the Editor open, use Meta's MCP servers rather than guessing:
  - `meta-xr-unity-runtime` compiles, lists errors, runs the tests and runs Meta's Project Setup Tool.
  - `meta-xr-operator` works in Play mode with the simulator: screenshots, head pose, controller input and the
    scene hierarchy.

  README explains how to connect them. Screenshot the simulator to check anything visual.
- With the Editor closed, use `pnpm quest:check`. Unity allows only one instance per project, so never run it
  while the Editor is open.
- Never mark permission, network or frame-time work as done from Editor evidence alone. Say it still needs step 5.
